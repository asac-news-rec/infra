# ADR-001: 외부에 공개하는 서버는 Cloud Run, 나머지는 GKE에 올린다

## 상태
Accepted (멘토 지시, 2026-11-03)

## 컨텍스트
프론트, 뉴스 백엔드, 로깅 서버는 인터넷에서 접근해야 한다. Airflow, MLflow, 추론 서버, Valkey 등은 내부에서만 쓴다. 팀은 서버 운영 인력이 적고 크레딧이 제한되어 있다.

## 결정
프론트, 뉴스 백엔드, 로깅 서버는 **Cloud Run**에 GitHub Actions로 직접 배포한다. 그 외는 **GKE**에 Helm 차트로 올리고 Argo CD가 반영한다.

## 근거
- Cloud Run은 외부 공개와 자동 확장이 단순하고, 쓰지 않을 때 비용이 줄어든다.
- GKE 내부 도구는 설정이 많아 GitOps(Argo CD)로 관리하는 것이 안전하다.
- 멘토가 이 구분을 지시했다.

## 결과
- 배포 경로가 두 가지가 된다(Actions → Cloud Run, 인프라 레포 → Argo CD → GKE).
- Cloud Run은 디스크가 유지되지 않으므로 로깅 서버의 저장 방식에 영향을 준다(ADR-003).

## 대안
- 전부 GKE: 외부 공개용 로드밸런서, 인증서 등을 직접 운영해야 해서 부담이 크다.
- 전부 Cloud Run: Airflow와 MLflow처럼 계속 켜 두는 도구에는 맞지 않는다.
